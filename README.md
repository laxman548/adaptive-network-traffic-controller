Adaptive Network Traffic Controller
A C++ project that aims to distribute HTTP requests across multiple backend servers by considering server load, latency, and health.
Current status: Day 1 foundation is complete. The current program stores and prints sample server metrics. HTTP request forwarding, live health checks, adaptive routing, Docker deployment, and performance comparisons are planned development steps—not implemented yet.

Project Goals
- Represent multiple backend servers and track their metrics.
- Select healthy servers using load and latency information.
- Detect unhealthy or unavailable backends.
- Distribute HTTP requests dynamically.
- Run the system locally with Docker.
- Compare adaptive routing with a Round Robin baseline.
Planned Architecture
                  Incoming HTTP requests
                           |
                           v
                Adaptive Traffic Controller
                           |
             Read server metrics and health
                           |
                           v
                  Routing decision
                           |
             +-------------+-------------+
             |             |             |
             v             v             v
          Server A      Server B      Server C
          Backend       Backend       Backend
The controller will eventually maintain a pool of backend servers, evaluate their current metrics, and route each request to an eligible server. The architecture will be implemented incrementally over the 30-day project.
Server Metrics
The initial C++ Server structure contains:
Field	Meaning
serverId	Unique name or identifier for a backend
activeRequests	Number of requests currently being processed
latency	Response-time measurement in milliseconds
healthy	Whether the backend is currently eligible to receive traffic


The Day 1 program uses three sample servers to demonstrate this data model.

Build and Run
Run these commands from the project root in PowerShell, with CMake and a MinGW-compatible compiler available on your PATH:
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
.\build\controller.exe
If the build directory has already been configured, rebuild and run with:
cmake --build build
.\build\controller.exe
Development Roadmap
The project will be developed in stages:
1. Foundation: environment setup, server data model, and metrics display.
2. Routing logic: choose an eligible backend using active requests and latency.
3. Baseline algorithm: implement Round Robin for comparison.
4. HTTP layer: receive requests and forward them to backend services.
5. Health monitoring: detect failed or unhealthy backends.
6. Adaptive routing: update routing decisions as server metrics change.
7. Containerization: run the controller and backend servers with Docker.
8. Evaluation: generate test traffic and compare adaptive routing with Round Robin.
